1. The Problem

A citizen asks a question in plain Khmer — can we find the one right article out of 1,976?

The Task

Khmer question → the correct statutory article, out of the full 1,976-article corpus, with no hints about which code or chapter to look in.

"តើកិច្ចសន្យាបង្កើតឡើងដោយរបៀបណា?"

("How is a contract formed?")

→ Civil Code Art. 336 (ការបង្កើតកិច្ចសន្យាដោយសំណើ និង ស្វីការ)

Why It's Hard

  • Vocabulary gap: citizens ask in everyday phrasing; statutes use formal legal terms. Keyword search (BM25) misses on wording alone in 57.5% of its failures (61 of 106 misses at k=5).
  • The source text itself is broken: official PDFs are typeset in an obsolete 1990s Khmer font (Limon), not Unicode — we had to build a converter before any of this could start (details in appendix).

2. Dataset & Four Approaches

Same corpus, same split, same loss for every approach — only architecture and training strategy differ

Corpus & Leakage Guards

  • 1,976 official Khmer articles — Civil Code 2007 (1,304) + Criminal Code 2009 (672), CC-BY-SA-4.0 from Open Development Cambodia.
  • The 200 test questions (and every article they cite) are excluded from training; article titles are stripped from training text; splits are fixed with seed 42; test sets are evaluated once.

All four approaches use the same contrastive loss (InfoNCE): pull the correct article closer to the question, push the other articles in the batch away. Only the encoder and training strategy change between them.

4. Why It Works

Learning curves explain the leaderboard — this is about capacity, pre-training and generalisation

A1 (from scratch) memorises the ~1,176 training pairs (train loss → 0.02) but validation loss stalls — classic overfitting with no pre-training to fall back on.

A2 (frozen) never overfits — the backbone is fixed — but it also can't adapt beyond what pre-training already knows.

A3 (fine-tuned) is the only one that both fits and generalises: pre-training + adaptation together.

Real example (Q&A backup has 3 more): "តើនរណាខ្លះអាចស្នើសុំឱ្យតុលាការប្រកាសបើកអាណាព្យាបាលទូទៅ?" — BM25 misses entirely (not in its top 10); A3 retrieves the correct article (Civil Code Art. 24) at rank 1.

5. Conclusion & Prototype

Three takeaways, one working assistant, and what's still missing

1

Pre-training is not optional at this data scale — the from-scratch BiLSTM (A1) fails outright (0.17 MRR@10).

2

A cheap frozen probe (A2) — 0.59M params, 6 seconds to train — already matches keyword search for free.

3

Full fine-tuning (A3) is what actually bridges "plain speech" and "legal speech," and is the model now live in our Khmer RAG assistant (FastAPI + Streamlit, <100 ms retrieval, citations checked automatically).

Limitations: two statutory codes only; 200 test questions leaves moderate confidence intervals; scanned laws (e.g., Labour Law) require legacy OCR and remain future work. All 4 architectures now feature complete hyperparameter tuning grids (see appendix).

A6. Before Any Model: Reading the PDFs at All

Official government PDFs are not Unicode — this had to be solved first

The Problem

ODC's official PDFs are typeset in the legacy Limon font family. The text layer stores raw Latin keystrokes, e.g. maRta 336>- — a Unicode-aware extractor would produce meaningless text.

Khmer also writes pre-base vowels (េ ែ ៃ) and subscript consonants before the consonant they visually belong after, so a simple character map is not enough.

Our Fix

  • Byte-level Limon → Unicode character map, built from the corpus's own glyph tables
  • A small finite-state reordering pass that puts pre-base vowels and subscripts back into logical Unicode order
  • Result: 100% consecutive article extraction across all 1,976 articles (Civil 1–1304, Criminal 1–672), verified against the source PDFs
